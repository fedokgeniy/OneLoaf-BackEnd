# OneLoaf data dictionary

> Generated by `tools/generate_data_dictionary.py` from the schema created by the migrations: types, keys, constraints, indexes, triggers and reference values are read from the PostgreSQL system catalog.

**DBMS:** PostgreSQL 16. **Schema:** `public`. **Tables:** 29 (plus the service table `__ef_migrations_history` with the history of applied migrations). **Layers:** one transactional (OLTP) layer with views on top of it, see [design.md](design.md#data-layers).

## Conventions

- Table and column names are `snake_case`. Primary keys are `uuid` with `DEFAULT gen_random_uuid()`; reference tables use a text code.
- Points in time are `timestamp with time zone` (stored in UTC); dates without time are `date`.
- Money and quantities are `numeric(p,s)`: exact decimal arithmetic without `float` rounding errors.
- Classifications with attributes (units, currencies, stage types, categories, flour types) are reference tables with foreign keys. Closed sets of states the logic depends on (statuses, roles, reminder kinds) are `varchar(32)` with a CHECK `ck_<table>_<column>`.
- JSON (`jsonb`) is used only in three columns with a documented and checked structure: `recipes.variant_overrides`, `published_recipes.snapshot`, `chat_messages.tool_payload` (see [design.md](design.md#json-columns)).
- Constraint names: `pk_` primary key, `fk_<table>_<referenced>_<column>` foreign key, `ux_` unique index, `ix_` index, `ck_` CHECK, `trg_` trigger.

**Key:** PK - primary key, FK - foreign key (referenced table in brackets), UQ - unique value. **Data quality:** [C] - guaranteed by a database constraint or trigger, [M] - monitored by the view `v_data_quality_issues` (the rule depends on time or on several tables and cannot be a constraint).
